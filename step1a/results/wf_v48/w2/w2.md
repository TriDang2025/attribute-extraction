## Expected vs got

1. New vs new: internet_options -> internet and parking_options -> parking: yes.
2. Mix: amenities (both sets) and services (dev50b): yes. Facilities (dev50b) is not caught.
3. Loop-1 overlap: menu_type -> cuisine (dev50) yes; cuisine_type (dev50b) no. In dev50b loop 1 the cuisine values are spread over
   cuisine / entity / str, and the loop-1 cuisine column holds other cuisines (lebanese, turkish). Value matching cannot link them; the
   column centroid also ranks cuisine only 3rd (0.68-0.76, below entity and restaurant name).

   "what day" sits only in loop-1 columns, which W2 does not touch.

## Design notes (please check)

- F3 l1_share 0.25 was added after the dev50b sweep: without it, one stray "free parking" in the 19-mention loop-1 "location part"
  makes parking a duplicate (dev50b, every tau). It changes nothing on dev50 (both dev50 joins have 0.31 and more).
- tau 0.8: dev50 gives the same 2 joins for tau 0.75-0.80; at 0.70 menu_type goes to "restaurant name" instead (sweep: tau_sweep.csv).
- F2 is a pair rule (two distinct other columns, neither >= 0.8 alone, together >= 0.8), not the literal "80% in other columns".
  The literal rule caught nothing on dev50b, because the three mixed hotel columns cover each other.
- F4 uses scikit-learn's generic English stop words (what, your, the, how, many), not a hand-made domain list.
- F4 also drops the bare value "parking" from the parking columns (5 mentions each, for example "cheap and has parking"). F2 and F1 still
  see the dropped values.
