# wf_v3.9 Colab batch contract (T4 reconcile of split parts, T8 A with a cue line)

Model and settings as v3.8: Qwen2.5-32B-Instruct-AWQ, temperature 0, guided JSON per job schema, one A100. All stage-1 prompts are built on the laptop, committed and pushed before the run. **Two stages in one Colab session:** stage 1 (reconcile, a_cue) is independent jobs; stage 2 (duplicate checks on the reconciled columns) is built on Colab from the stage-1 reconcile responses by `scripts/batch_stage2_v39.py` (notebook cell 8).

## Input columns and parts
Columns = `s1a/batch_v38.column_table` of **A s012 with the split pass**, Step 1a v2.2, dev50 and dev50b, loaded as `scripts/batch_build_v38.py` loads them (stops unless 67 / 56 columns). A **part** = a group of the A s012 variant with `source == "split"` (attr_id `<cluster>/<k>`) that has at least one mention: 80 split groups exist (dev50 48, dev50b 32), 1 has no mention (dev50 restaurant `E2#14/0`) and gets no job, so **79 parts** (dev50: train 13, hotel 18, restaurant 16; dev50b: train 4, hotel 16, restaurant 12; `parts.csv`).

## Families
1. **reconcile** (T4, stage 1): one job per part x candidate order (seed 0 and 1) = 79 x 2 = **158** (dev50 94, dev50b 64). Prompt: the part (name = its column's name, description = the `role` the v3.1 split pass gave the part, "" when none, 5 example turns with the value marked `[[value]]`, sampled with `batch_v38.sample_examples`, seed 0) and its **5 nearest other columns** of the same entity (cosine of bge-m3 centroids, `batch_v38.centroids`; the part's own column is excluded; a column with no mention is never a candidate), each with name, description ("" not shown) and 3 most frequent values. The 5 candidates are listed in an order fixed by (order seed, set, entity, part id) (`batch_v39.shuffled_order`; the same 5 columns in both orders, only the order differs). Question: "Is this part the same attribute, with the same role, as one of these columns? Answer that column's name, or none." Format `reconcile` (`llm_cache.parse_reconcile`): schema `{"unit_id": enum [part id], "reason": str (at most 25 words, written first), "same_as": enum [the 5 names] + ["none"]}`. run_tag `o0` / `o1`. max_tokens 256.
2. **a_cue** (T8, stage 1): A's v2 entity prompt (`pilot_build_v37.a_prompts`, orders s0 / s1 / s2, k from the same fit) with **one sentence added** to the instruction, `pilot_input.CUE_LINE` (question phrases such as "what day", "how many tickets" get the label `attribute_cue`, not a column), after the noise sentence where `INSTRUCTION_V2_AE` puts its rule; nothing else changes (the diff to the v3.1 prompt is that one line). Schema = `schema_v2` with the description of `attribute` extended by "attribute_cue" (the property is a free string, so guided decoding already allows it). 3 orders x 3 entities x 2 sets = **18** (dev50 9, dev50b 9), names `<ent>_acue_<set>_s<n>`, max_tokens `pilot_build_v31.max_tokens` (12,000 here). Manifest format `v2`; `llm_cache.parse_job` flags `attribute_cue` as "not in the attribute list", so the notebook reads this family with `batch_v39.parse_job(..., family)` (`parse_a_cue`: the same checks without that one error); `llm_cache` is not edited.
3. **dupcheck_rc** (T4, stage 2): the v3.8 duplicate check (`batch_v38.render_dupcheck`, `schema_dupcheck`, format `dupcheck`, max_tokens 1024) on the **reconciled** columns, one per set x entity x reconcile order = 2 x 3 x 2 = **12**, names `dupcheck_<set>_rc<order>_<ent>`. Joins are applied by `batch_v39.apply_reconcile` (pure; local scoring reuses it): a part with an answer joins its mentions to the chosen column; `none`, an answer with a parse error, a missing response or a name outside the candidates keeps the part; a join whose two column names form a role pair (`batch_v38.check_joins`, `role_guard` start/end place and earliest/latest time, names only, never the GT) is blocked and keeps the part; a column that loses a part and has no mention left is dropped; columns are renumbered 1..n by name. The check on the dupcheck answers themselves (v3.8 `check_joins`) is applied when scoring, as in v3.8.

All jobs are round 0. Every prompt must stay below 30,000 tokens; the notebook counts exact tokens and stops above that (largest estimate: 13,980).

## File layout (`results/loop1_v39/colab/`)
- Stage 1 (`scripts/batch_build_v39.py`, needs the gitignored `vectors.npz` of graph_v22_dev50 / dev50b): `prompts/*.txt + *.schema.json`, `manifest.json` (family reconcile | a_cue; reconcile jobs carry `pid`, `column`, `order_seed`, `candidates` = [{cid, name}] in the order shown), `columns.json` ({set: {ent: {entity, columns (with pools), parts}}}, the only input of stage 2 besides the responses), `parts.csv`, `reconcile_examples.csv` (job, example id, mention_id, cluster_id, part, value, order seed), `examples.csv` (A-cue examples, the v3.7 format `ex_id, entity, cluster_id, mention_id, variant`), `prompt_stats.md`, `prompt_samples.md`.
- Stage 2 (on Colab): `prompts/dupcheck_*_rc*_*.txt + schema`, `manifest_stage2.json` (family dupcheck_rc, stage 2), `reconciled_columns.json` ({set: {ent: {order: {columns, report}}}}), `reconcile_joins.csv` (every part, answer, status joined | none | blocked | invalid), `stage2_stats.md`.
- Responses: `responses/<job>.jsonl` (llm_cache rows). Notebook `colab/S1A_llm_v39_colab.ipynb` (copy of v3.8: branch wf-v3.9, folder loop1_v39): load model, stage 1, cell 8 builds and runs stage 2, cell 9 parse check, cell 10 summary, cell 11 commit and push (`colab/sync.sh push-results ... loop1_v39/colab`). Secrets only as Colab Secrets HF_TOKEN / GH_TOKEN.
